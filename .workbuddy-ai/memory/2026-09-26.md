### The one real bug, and the two-layer trap behind it

`GET /api/education-records` was **400 on live for every role**, and predated the merge (master has the
same `orderBy` and the same missing column). It was masked twice over:

1. `education_records` was provisioned before `createdAt`/`updatedAt` were in its `CREATE TABLE` body.

### `isSnapshot` — a page-killing crash, found by accident

Chasing a different problem, a synthetic Houseparent session crashed `/violations` with
`Cannot read properties of undefined (reading 'some')`. Root cause: `isSnapshot()` returned true for
**any object carrying a `fullAccess` key**, and `AuthContext` stores `fullAccess` on the session user
next to a null `access`. So the user object was mistaken for a resolved snapshot and the next read,
`snapshot.modules.some(...)`, threw. Reachable for any session restored from localStorage with no
`access` field — every role that is not a full-access role. A real snapshot always carries `modules`,
so the guard now requires `Array.isArray(modules)`.

**The near-miss matters more than the bug**: my first fixture set `access: null` while keeping
`fullAccess: false`, and I nearly wrote it off as a fixture artifact. It *was* unrealistic for a
session created by the current login (which always ships `access`) — but only because the login
payload happens to supply it. Building the fixture from the server's own `buildAccessSnapshot()` +
`listAccessibleMenus()` removed the guesswork, and the `access`-less case was then kept as a real
regression case. **Derive fixtures from the server's own code; do not hand-write a session shape.**

## Username-rename cascade (13:10)

Shipped `8d3feb4`. `updateById` in `userController` now carries a username change across
`USERNAME_REFERENCE_COLUMNS` — 83 columns over 30 tables.

**The rule that decided the column set**, and the one to reuse: cascade where the name is a **link to an
account**, leave it where the name is **what was printed on an official form**. Excluded for that reason:
`incidentReports.reportedBy / checkedBy / notedBy` (Form 08 pre-printed names, drawn beside signatures),
`triRecords.houseparentSignedBy`, `anecdotalReports.houseparentName`, `admissions.houseparentOnDuty`,
`quarterlyProgressReports.assignedToName`. Included: `incidentReports.verifiedBy / psychVerifiedBy /
swVerifiedBy`, which the controller writes as `verifiedBy || req.user?.username`.

Two real links were broken by a rename before this: `documentOwnerMatchesUser` (documents stop belonging
to their uploader) and `notifyAuthor` (`WHERE username = ? OR id = ?` fails to resolve, so the author is
never notified that their report was returned). Both key on `username`, not `displayName` — a
**display-name** change was always harmless, because nothing anywhere links on `displayName`.

Verification that made this safe to ship:
- Every one of the 83 columns checked against `expectedSchema.json`, with `anecdotalReports` falling back
  to its lazy `CREATE TABLE` in `anecdotalReportController` — that table is **not** in
  `expectedSchema.json`, same as `education_records`. Zero mismatches, zero unvalidated tables.
- Impact simulated against the live `/store` snapshot: renaming `SW-Aldrin` touches 20 rows (14 documents),
  `Nurse-ian` 8, `houseparent1` 22, `centerhead` 290. `/store` covers only 19 of the 30 tables, so the real
  totals are higher.
- Matched with `=` on the trimmed old username, so `System` / `system` sentinels and human-typed names are
  never rewritten. `ER_NO_SUCH_TABLE` / `ER_BAD_FIELD_ERROR` are swallowed per column so a database behind
  this build cannot fail a rename that has already committed; any other error is logged.

**Column types matter for this kind of sweep:** `alerts.readBy` is a single `varchar(100)` username, not a
JSON array — worth checking before assuming a `readBy`-style column needs JSON surgery. All the cascade
columns are `varchar(100)`.

## Medical record → Houseparent notification + deep link (14:05)

The gap was real on both halves. Shipped `b32b7d6`, repairs in `3b9bb79`.

**No notification existed.** `healthController.js` contains no `notify` call at all, and
`documentController.create`'s only upload alert targets the **reviewers** of a Psychological Assessment

- `rbac.test.js` → "the Nurse dashboard links only to pages the Nurse may open" matches
